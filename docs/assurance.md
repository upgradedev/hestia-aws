## Legal assessment boundary

EU AI Act applicability, GDPR obligations and consumer-law remedies need a separate legal review. No risk classification, certification or article-by-article assessment is established here, and a date comparison, a citation, a model briefing or an approval button cannot supply one. The prepared notice cites Directive (EU) 2019/771, Articles 10 to 17, as general reference subject to applicability, names Directive (EU) 2024/1799 among the rules to check, points to the European Commission's Consumer Redress Portal and says the draft does not determine legal eligibility. Jurisdiction-specific applicability remains unverified.

## Data handling inventory

The sample household is fictional. The product also invites visitors to add their own appliances, repairs and receipts, and no copy asks for fictional details, so a private copy or pasted text may contain real personal data. Nothing filters it.

| Surface | Behavior | Open question |
|---|---|---|
| Sample records | a fictional household with real retailer names and `.example.gr` contact addresses | not a representative household cohort |
| Browser session | the capability is kept in session storage under `hestia.demo-session.v1` | session expiry ends access, not storage |
| What a private copy stores | registry appliances with brand, model, serial, purchase date and price, seller name and email, receipt reference and saved links; repairs with date, amount and issue; transactions, subscriptions and receipt links; staged drafts with proposed, original and corrected records; intake provenance; case notes, evidence references, planning dates and attested outcomes; the last five briefings with their tool traces. All of it sits in the copy's `state.json` | user-entered content is not authenticated or screened for personal data |
| Model input for a review | the system prompt, the review prompt (appliance ids with item names, and the review date), the four tool schemas and tool outputs clipped to 1600 characters each, sent through the Bedrock client in `eu-west-1` to the EU inference profile | Bedrock data handling, and where the EU profile processes a request, need separate confirmation; no local PII filter runs first |
| Model input for pasted text | up to 6000 characters, sent verbatim after a document type hint with the extraction prompt, through the same client. The text and the hint are not stored: the draft keeps the SHA-256, byte count, normalised records, model id, token usage and duration, and an audit event keeps the SHA-256 on success and on failure | the same Bedrock question; the SHA-256 makes identical text linkable within one private copy |
| State storage | one `state.json` per private copy (at most 262144 bytes) under `demo/workspaces/<id>/`, plus daily counters under `demo/workspaces/_usage/`; the bucket is versioned, encrypted with SSE-S3, TLS only and retained if the stack is deleted | the 90-day expiry rule matches only the unused `audit/` prefix, so current private copies never expire; noncurrent versions expire after 30 days; both roles deny deletes, so no erasure path exists, and backups are not configured |
| Third parties | on the server, Amazon Bedrock is the only third party that receives household text. In the browser, a "Search" link the visitor clicks sends the appliance brand and model, or the item name, to duckduckgo.com, and a saved link opens the address the household entered | bank, mailbox and retailer sync, image OCR and SES are not connected |
| Operational logs | one log group per function with 14-day retention; the application writes one JSON line when a text reading fails (event, reason, duration and whether it counted, with no text or hash) | the templates configure no API Gateway access logs and no CloudFront logs; platform log lines are not inventoried |

Source paths: `frontend/src/useDemoSession.ts`, `frontend/src/components/RegistryModal.tsx`, `frontend/src/components/RecordsView.tsx`, `src/hestia/app/api.py`, `src/hestia/app/agent.py`, `src/hestia/app/intake.py`, `src/hestia/domain/intake.py`, `src/hestia/app/cases.py`, `src/hestia/adapters/storage.py`, `infra/hestia_api_stack.py`, `infra/frontend_stack.py`. No claim of collecting nothing, guaranteed erasure or absence of third-party processing follows from this inventory.

## Provenance

The CloudFront and S3 hosting template (`infra/frontend_stack.py`) and the video production tooling (`video/`, `web/video/`, `scripts/verify_video_sync.py`) are reused from the author's earlier projects. Everything else in this repository was written for Hestia. The business rules follow the text of Directive (EU) 2019/771 and general household bookkeeping practice, and no customer or private data was used.
